1. Naming de ramas: Usamos GitFlow con ramas main, develop, feature/ y hotfix/.
2. Convenciones de commits: Mensajes con prefijos feat: (mejoras), fix: (errores) y docs: (documentos).
3. Flujos de merge: Todo cambio se integra mediante Pull Requests hacia develop o main.
4. Estrategia de revisión: El compañero debe revisar y aprobar el Pull Request en GitHub antes de hacer el merge final.
